# AI 辅助测试工作流实践：Hermes + 飞书 + Cursor 全链路自动化

> 把需求、用例生成、测试执行、Bug 记录、报告推送串成全自动流水线。测试工程师从"点页面"变成"管流程"。

## 为什么做这个

传统测试流程的痛点：
- 需求 → 用例 → 执行 → 报告，大量重复性手工操作
- 需求文档、用例、报告散落在多个工具，来回切换
- 历史经验无法复用，每次从零开始

## 整体架构

```
┌─────────────────────────────────────────────┐
│             飞书（协作入口/出口）               │
│  发需求 → 收用例 → 确认 → 收报告 → 收Bug单    │
└───────────────┬─────────────────────────────┘
                │ Feishu Gateway
                ▼
┌─────────────────────────────────────────────┐
│          Hermes Agent（测试执行中枢）          │
│  ① 生成8维度用例 ② 浏览器测试+截图            │
│  ③ 缺陷记录(带代码定位) ④ 报告生成            │
└───────────────┬─────────────────────────────┘
                │ MCP
                ▼
┌─────────────────────────────────────────────┐
│       Cursor（代码修复/测试开发）              │
│  定位Bug → 修复 → pytest验证 → 推送飞书      │
└─────────────────────────────────────────────┘
```

## 核心流程

### 1. 需求发起（飞书）
产品在飞书群发需求文档 → @Hermes → 自动触发

### 2. 用例生成（Hermes）
- 读取需求 → RAG 检索历史经验 → 生成 8 维度测试用例
- 标注每个用例对应的 pytest 脚本
- 生成 Markdown 用例文档 → 发到飞书群等确认

### 3. 执行测试（Hermes）
- 接口层：pytest 全量回归
- UI 层：浏览器自动化 + 截图取证
- 发现 Bug → 自动生成缺陷单（含代码位置）→ 推飞书

### 4. 代码修复（Cursor）
- 开发者打开项目 → 按缺陷单定位 → 修复 → pytest 验证
- 通过 MCP 自动推送结果到飞书

## 技术亮点

### 8 维度测试用例覆盖
| 维度 | 含义 |
|------|------|
| N | Normal 正常流程 |
| B | Boundary 边界值 |
| T | Type 类型错误 |
| E | Exception 异常 |
| A | Auth 权限 |
| D | Dependency 依赖 |
| I | Idempotent 幂等 |
| S | Security 安全 |

### RAG 知识库沉淀
- 历史需求、用例、Bug 复盘自动入库
- 生成新用例时自动检索复用，不重复造轮子

## 落地效果

- ✅ 需求 → 用例：从人工 1 天 → **分钟级**
- ✅ 测试执行：自动化跑完 110+ 用例，无需值守
- ✅ Bug 记录：自动带代码定位，减少沟通成本
- ✅ 报告：自动汇总截图 + 通过率，推送到飞书群

## 可复用性

这套架构不绑定具体被测系统，任何 Web 应用 + pytest 项目都能复用：
- 换被测系统：改 `target-systems.yaml` 配置即可
- 换协作平台：Hermes 支持飞书/钉钉/微信/Telegram 多平台
